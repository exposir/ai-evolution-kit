## 一、基础概念

### Embedding 是什么？

**定义**: 将文本转换为高维向量的过程  
**目的**: 让计算机理解语义相似性  
**示例**: "猫"和"猫咪"的 Embedding 向量很接近

**常见模型**:
- OpenAI text-embedding-3-small (1536 维)
- 智谱 embedding-3 (2048 维)

---

### Token 是什么？

**定义**: 文本的最小单位  
**换算**: 1 token ≈ 0.75 个英文单词 ≈ 1.5 个中文字符  
**影响**: API 成本、上下文窗口大小  
**优化**: Prompt 压缩、缓存常见问题

---

### Temperature 是什么？

**定义**: 控制生成随机性的参数（0-2）  
**效果**:
- 0: 确定性输出，适合事实问答
- 1: 默认值，平衡创造性和准确性
- 2: 高度随机，适合创意写作

---

## 二、向量检索

### 为什么用余弦相似度？

**原理**: 计算向量夹角，范围 [-1, 1]，1 表示完全相同  
**优势**: 不受向量模长影响，只关注方向  
**对比**:
- 欧氏距离: 关注绝对距离，受模长影响
- 点积: 受模长影响，需要归一化

---

### 如何选择 Chunk Size？

**权衡**:
- 太小: 语义不完整，检索不准
- 太大: 包含无关信息，干扰生成

**推荐值**:
- 技术文档: 512 tokens
- 对话记录: 256 tokens
- 长文章: 1024 tokens

**动态策略**: 根据文档类型自适应

---

### 混合检索的优势？

**问题**: 纯向量检索对专有名词不敏感  
**方案**: Vector Search（语义）+ Keyword Search（精确匹配）  
**示例**: 查询"GPT-4"，关键词搜索比向量搜索更准

## 三、Agent 编排

### LangGraph 的核心概念？

**三要素**:
1. **State**: 用 Annotation 定义，reducer 累积消息
2. **Node**: 执行节点（agent、tools）
3. **Edge**: 连接关系（普通边、条件边）

**执行流程**: START → agent → [condition] → tools/END

---

### 如何实现自我修复？

**方案**: Conditional Edge + retryCount

```typescript
graph.addConditionalEdges('validation', (state) => 
  state.errors && state.retryCount < 3 ? 'retry' : 'finish'
);
```

---

### 人机协作怎么做？

**关键**: `interruptBefore` + `MemorySaver`

```typescript
const app = graph.compile({ 
  checkpointer: new MemorySaver(),
  interruptBefore: ['human_review']
});

// 执行到 human_review 节点时暂停
await app.invoke(input);

// 人工审批后恢复
await app.invoke(null, { configurable: { thread_id } });
```

### streamObject 的原理？

**问题**: 结构化输出如何流式解析？  
**方案**: 逐 Token 解析 JSON，遇到完整字段立即更新

```typescript
const { object } = useObject({
  api: '/api/structured',
  schema: z.object({ name: z.string(), age: z.number() }),
});

// object 会逐字段更新
// { name: "Al" } → { name: "Alice" } → { name: "Alice", age: 25 }
```

## 五、生产部署

### 如何控制成本？

**策略**:
1. **缓存**: 相同问题直接返回
2. **Prompt 压缩**: 移除冗余信息
3. **模型选择**: GPT-3.5 vs GPT-4
4. **批量请求**: 减少 API 调用次数

**实际案例**:
- POST 缓存命中率 30% → 节省 30% 成本
- 批量 Embedding → 性能提升 33 倍

---

### 如何监控 LLM 应用？

**关键指标**:
- 调用次数、成功率、延迟
- Token 消耗量（成本）
- 用户满意度（点赞/点踩）

**工具**: LangSmith / Langfuse

---

### 安全问题怎么处理？

**威胁**:
1. **Prompt 注入**: 用户输入覆盖系统 Prompt
2. **数据泄漏**: LLM 输出敏感信息
3. **API 滥用**: 恶意请求消耗成本

**防御**:
1. **输入验证**: class-validator 过滤
2. **输出过滤**: 检测敏感信息
3. **限流 + 认证**: 三级限流 + API Key

## 六、常见对比

### LangGraph vs LangChain

| 维度 | LangChain | LangGraph |
|------|-----------|-----------|
| 流程控制 | 链式 | 图结构 |
| 分支支持 | 差 | 好 |
| 状态管理 | 隐式 | 显式 |
| 适用场景 | 简单 | 复杂 |

---

### Supabase vs Pinecone

| 维度 | Pinecone | Supabase |
|------|----------|----------|
| 类型 | 专业向量库 | PostgreSQL + pgvector |
| 成本 | 按量计费 | 免费额度慷慨 |
| 透明度 | 黑盒 | SQL 可见 |
| 推荐场景 | 生产环境 | 学习 / MVP |

---

### Next.js vs NestJS

| 维度 | Next.js | NestJS |
|------|---------|--------|
| 定位 | 前端框架 | 后端框架 |
| 路由 | App Router | Controller |
| 中间件 | Middleware | Guard/Interceptor |
| 状态 | React Hooks | DI 容器 |
