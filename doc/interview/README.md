## 使用流程

### Phase 1: 面试前 1 天
**目标**: 建立完整知识体系

1. **通读核心文档** (2-3 小时)
   - [01-项目概览与价值定位](./01-项目概览与价值定位.md#) - 熟悉 3 分钟电梯演讲
   - [04-架构设计与演进路径](./04-架构设计与演进路径.md#) - 理解 M1→M5 演进逻辑
   - [02-技术亮点与差异化优势](./02-技术亮点与差异化优势.md#) - 记忆手写算法要点

2. **代码复习** (1-2 小时)
   - [packages/01-runtime-lab/src/03-loop.ts](../../packages/01-runtime-lab/src/03-loop.ts#) - ReAct 循环
   - [packages/01-runtime-lab/src/08-search.ts](../../packages/01-runtime-lab/src/08-search.ts#) - 余弦相似度
   - [packages/03-agent-brain/src/13-self-correction.ts](../../packages/03-agent-brain/src/13-self-correction.ts#) - 自我修复回路

3. **话术演练** (1 小时)
   - 对着镜子练习 3 分钟电梯演讲
   - 录音回放，优化表达

### Phase 2: 面试前 1 小时
**目标**: 激活记忆，进入状态

1. **重点复习** (30 分钟)
   - [07-面试话术与回答模板](./07-面试话术与回答模板.md#) - STAR 法则模板
   - [03-核心算法与原理实现](./03-核心算法与原理实现.md#) - 白板编程准备

2. **心理准备** (10 分钟)
   - 深呼吸，回忆项目亮点
   - 准备好 2-3 个踩坑经验（证明真实实战）

3. **环境检查** (10 分钟)
   - 网络、摄像头、麦克风
   - 关闭无关软件
   - 准备草稿纸（白板编程用）

### Phase 3: 面试中
**目标**: 结构化回答，展示深度

1. **项目介绍**
   - 使用 [01-项目概览](./01-项目概览与价值定位.md#) 的 3 分钟脚本
   - 强调 3 个核心亮点：手写算法 + 架构演进 + 生产特性

2. **技术深挖**
   - 遇到算法问题 → [03-核心算法](./03-核心算法与原理实现.md#)
   - 遇到架构问题 → [04-架构设计](./04-架构设计与演进路径.md#)
   - 遇到系统设计 → [05-生产能力](./05-生产级工程能力.md#)

3. **快速查阅**
   - 卡壳时查阅 [08-速查手册](./08-技术问题速查手册.md#)
   - 不确定细节时说："让我查阅一下我的笔记"（展示真实性）

### Phase 4: 面试后
**目标**: 迭代优化，持续改进

1. **复盘记录** (30 分钟)
   - 记录面试官的问题（尤其是卡壳的）
   - 评估回答质量（哪些回答不够好）

2. **文档更新**
   - 将新问题加入 [08-速查手册](./08-技术问题速查手册.md#)
   - 优化 [07-话术模板](./07-面试话术与回答模板.md#)

3. **知识补齐**
   - 回答不好的技术点重新学习
   - 更新相关文档

## 核心面试策略

### 三层回答法（现象 → 本质 → 哲学）

**示例：为什么需要 LangGraph？**

**现象层**（直接回答）:
"手写 while 循环实现 ReAct 时，代码 50 行。加入自我修复需要嵌套 if/else，变 100 行。复杂逻辑难维护。"

**本质层**（深层原因）:
"命令式编程混合了'做什么'和'怎么做'，导致状态管理混乱。缺少结构化的流程描述。"

**哲学层**（设计理念）:
"声明式优于命令式。图结构天然描述流程分支。状态显式管理（Annotation）避免隐式耦合。"

**回到现象**（解决方案）:
"LangGraph 版本只需要 30 行，用图结构描述流程，ConditionalEdge 天然支持多分支。"

### STAR 法则模板

**Situation**: 背景是什么？
**Task**: 要解决什么问题？
**Action**: 我做了什么？
**Result**: 结果如何？

详见 [07-面试话术与回答模板](./07-面试话术与回答模板.md#)

### 差异化定位

**vs 后端工程师**: 对交互体验的敏感度（流式 UI、状态管理、组件化）
**vs 纯前端工程师**: AI 原理理解（手写 ReAct、余弦相似度）+ 全栈能力（NestJS、Redis）

详见 [06-前端工程师转型优势](./06-前端工程师转型优势.md#)

## 常见问题 FAQ

### Q: 如何在 3 分钟内讲清楚项目？
**A**: 使用 [01-项目概览](./01-项目概览与价值定位.md#) 的电梯演讲脚本：
- [0-30s] 问题背景
- [30s-1m30s] 解决方案（5 个 Milestone）
- [1m30s-3m] 技术亮点（3 个核心）

### Q: 如何证明不是调包侠？
**A**: 展示手写算法：
- 余弦相似度（能白板复现）
- ReAct 循环（理解状态机转换）
- 递归文本切分（策略模式）

详见 [02-技术亮点](./02-技术亮点与差异化优势.md#)

### Q: 如何回答"你的最大难点是什么"？
**A**: 选择一个有深度的点展开，推荐：
- **架构演进**（体现系统思维）：while → StateGraph 的重构过程
- **生成式 UI**（体现前端优势）：AI 返回 JSON 到组件渲染的类型安全设计

详见 [07-面试话术](./07-面试话术与回答模板.md#q2-你的项目最大的技术难点是什么)

### Q: 如何应对白板编程？
**A**: 提前准备核心算法：
- 余弦相似度（必背）
- ReAct 循环核心逻辑
- 递归文本切分

详见 [03-核心算法](./03-核心算法与原理实现.md#)
