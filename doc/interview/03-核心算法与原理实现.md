## 一、向量检索核心算法

### 1. 余弦相似度（必背）

#### 数学公式

```
similarity = cos(θ) = (A · B) / (||A|| × ||B||)

其中:
- A · B = Σ(Ai × Bi)  // 点积
- ||A|| = √(Σ(Ai²))   // 模长
- ||B|| = √(Σ(Bi²))
```

#### 代码实现

```typescript
function cosineSimilarity(vecA: number[], vecB: number[]): number {
  let dotProduct = 0;
  let normA = 0;
  let normB = 0;

  for (let i = 0; i < vecA.length; i++) {
    dotProduct += vecA[i] * vecB[i];
    normA += vecA[i] * vecA[i];
    normB += vecB[i] * vecB[i];
  }

  return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB));
}
```

**时间复杂度**: O(n)，n 是向量维度  
**空间复杂度**: O(1)

#### 优化版本

```typescript
// 批量计算时复用模长
class VectorSearch {
  private cachedNorms = new Map<string, number>();

  similarity(vecA: number[], vecB: number[], idA?: string, idB?: string): number {
    let dotProduct = 0;
    const normA = idA && this.cachedNorms.has(idA)
      ? this.cachedNorms.get(idA)!
      : this.computeNorm(vecA, idA);
    const normB = idB && this.cachedNorms.has(idB)
      ? this.cachedNorms.get(idB)!
      : this.computeNorm(vecB, idB);

    for (let i = 0; i < vecA.length; i++) {
      dotProduct += vecA[i] * vecB[i];
    }

    return dotProduct / (normA * normB);
  }

  private computeNorm(vec: number[], id?: string): number {
    let sum = 0;
    for (const val of vec) {
      sum += val * val;
    }
    const norm = Math.sqrt(sum);
    if (id) this.cachedNorms.set(id, norm);
    return norm;
  }
}
```

#### 面试追问

**Q**: 为什么用余弦而非欧氏距离？  
**A**: 余弦关注方向，欧氏关注距离。文本 Embedding 是高维空间的方向向量，更关心语义方向而非绝对值。

**Q**: 如果向量是稀疏的怎么优化？  
**A**: 只计算非零元素的点积，跳过零值。

## 二、Agent 编排核心

### 1. ReAct 循环（手写版 vs LangGraph 版）

#### 手写版 (Ch3)

```typescript
async function reactAgent(query: string, tools: Tool[]) {
  const messages: Message[] = [{ role: 'user', content: query }];
  const maxIterations = 10;
  let currentIteration = 0;

  while (currentIteration < maxIterations) {
    const response = await openai.chat.completions.create({
      model: 'gpt-4',
      messages,
      tools: tools.map(t => ({
        type: 'function',
        function: {
          name: t.name,
          description: t.description,
          parameters: t.schema,
        },
      })),
    });

    const message = response.choices[0].message;
    messages.push(message);

    // 终止条件
    if (!message.tool_calls) {
      return message.content;
    }

    // 执行工具
    for (const call of message.tool_calls) {
      const tool = tools.find(t => t.name === call.function.name);
      const args = JSON.parse(call.function.arguments);
      const result = await tool!.execute(args);

      messages.push({
        role: 'tool',
        tool_call_id: call.id,
        content: JSON.stringify(result),
      });
    }

    currentIteration++;
  }

  throw new Error('Max iterations exceeded');
}
```

```typescript
const graph = new StateGraph(AgentState)

  .addNode('tools', toolNode)
  .addEdge(START, 'agent')

    tools: 'tools',

  .addEdge('tools', 'agent')
  .compile();
```

## 三、文本处理算法

### 1. 递归文本切分 (Ch9)

#### 问题

固定长度切分会破坏语义。

#### 方案

按 段落 → 句子 → 字符 递归切分。

#### 代码实现

```typescript
interface SplitterConfig {
  chunkSize: number;
  chunkOverlap: number;
}

class RecursiveTextSplitter {
  private separators = ['\n\n', '\n', '. ', ' '];
  private config: SplitterConfig;

  constructor(config: SplitterConfig) {
    this.config = config;
  }

  split(text: string): string[] {
    return this.recursiveSplit(text, 0);
  }

  private recursiveSplit(text: string, level: number): string[] {
    if (text.length <= this.config.chunkSize) {
      return [text];
    }

    // 尝试当前层级的分隔符
    const sep = this.separators[level];
    const parts = text.split(sep);
    const chunks: string[] = [];
    let current = '';

    for (const part of parts) {
      const potentialChunk = current ? current + sep + part : part;

      if (potentialChunk.length > this.config.chunkSize) {
        // 超长了，保存当前块
        if (current) {
          chunks.push(current);
          current = part;
        } else {
          // part 本身就超长，需要降级切分
          current = '';
          chunks.push(...this.handleOversizedPart(part, level));
        }
      } else {
        current = potentialChunk;
      }
    }

    if (current) {
      chunks.push(current);
    }

    // 添加 overlap
    return this.addOverlap(chunks);
  }

  private handleOversizedPart(part: string, level: number): string[] {
    if (level < this.separators.length - 1) {
      // 还有更细粒度的分隔符，递归切分
      return this.recursiveSplit(part, level + 1);
    } else {
      // 已经是最细粒度，暴力按字符切
      return this.forceChunk(part);
    }
  }

  private forceChunk(text: string): string[] {
    const chunks: string[] = [];
    for (let i = 0; i < text.length; i += this.config.chunkSize) {
      chunks.push(text.slice(i, i + this.config.chunkSize));
    }
    return chunks;
  }

  private addOverlap(chunks: string[]): string[] {
    if (this.config.chunkOverlap === 0 || chunks.length <= 1) {
      return chunks;
    }

    const result: string[] = [];
    for (let i = 0; i < chunks.length; i++) {
      if (i === 0) {
        result.push(chunks[i]);
      } else {
        const prevChunk = chunks[i - 1];
        const overlap = prevChunk.slice(-this.config.chunkOverlap);
        result.push(overlap + chunks[i]);
      }
    }
    return result;
  }
}
```

#### 使用示例

```typescript
const splitter = new RecursiveTextSplitter({
  chunkSize: 512,
  chunkOverlap: 50,
});

const text = `
段落 1...

段落 2...

段落 3...
`;

const chunks = splitter.split(text);
```

#### 设计亮点

- 优先保持段落完整性
- 超长段落降级到句子级别
- chunkOverlap 保证跨块语义连续
- 最终兜底：暴力按字符切

## 四、性能优化案例

### 1. 批量 Embedding 优化 (Ch10)

#### 问题

逐条调用 Embedding API 太慢，且容易触发 Rate Limit。

#### 方案

批量请求 + 错误重试。

```typescript
async function batchGetEmbeddings(
  texts: string[],
  batchSize = 100
): Promise<number[][]> {
  const results: number[][] = [];

  for (let i = 0; i < texts.length; i += batchSize) {
    const batch = texts.slice(i, i + batchSize);
    
    try {
      const response = await openai.embeddings.create({
        model: 'text-embedding-3-small',
        input: batch,
      });
      results.push(...response.data.map(d => d.embedding));
    } catch (error) {
      if (error.status === 429) {
        // Rate limit，等待后重试
        await sleep(5000);
        i -= batchSize; // 重试当前批次
        continue;
      }
      throw error;
    }

    // Rate Limit 控制
    if (i + batchSize < texts.length) {
      await sleep(1000); // 1s 间隔
    }
  }

  return results;
}
```

#### 性能提升

- 单条请求: 1000 条耗时 ~500s
- 批量请求: 1000 条耗时 ~15s
- **提升: 33 倍**

### 1. Message 数组维护 (Ch3)

#### 核心数据结构

```typescript
type Message =
  | { role: 'system'; content: string }
  | { role: 'user'; content: string }
  | { role: 'assistant'; content: string; tool_calls?: ToolCall[] }
  | { role: 'tool'; tool_call_id: string; content: string };

interface ToolCall {
  id: string;
  type: 'function';
  function: {
    name: string;
    arguments: string; // JSON string
  };
}
```

#### 关键操作

```typescript
// 1. 添加用户消息
messages.push({ role: 'user', content: query });

messages.push(response.choices[0].message);

// 3. 添加工具执行结果
messages.push({
  role: 'tool',
  tool_call_id: call.id,

// 4. 上下文窗口管理（保留最近 N 条）
const recentMessages = messages.slice(-10);
```

#### 面试追问

**Q**: 如何处理超长上下文？  
**A**: 
1. 滑动窗口：只保留最近 N 条消息
2. 摘要压缩：用 LLM 压缩历史对话
3. 向量检索：检索相关历史消息

1. **余弦相似度**

   ```typescript

   ```

### 复杂度分析

| 算法 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| 余弦相似度 | O(n) | O(1) |
| ReAct 循环 | O(k × m) | O(n) |
| 递归切分 | O(n) | O(n) |

其中:
- n: 向量维度 / 文本长度
- k: 循环次数
- m: 每次 LLM 调用时间
