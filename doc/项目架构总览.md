## 四、模块详解

### 1. `01-runtime-lab` - AI 运行时基础实验室

**核心能力**: 给 AI 装上"手"（Tools）和"眼"（RAG）

| 章节 | 文件               | 核心概念                                   |
| ---- | ------------------ | ------------------------------------------ |
| Ch1  | `01-chat.ts`       | 裸金属对话，上下文记忆 `messages.push()`   |
| Ch2  | `02-tools.ts`      | Tool 定义，Zod Schema → JSON Schema        |
| Ch3  | `03-loop.ts`       | ReAct 循环 `while (response.tool_calls)`   |
| Ch4  | `04-system.ts`     | 文件系统交互，赋予 AI 实权                 |
| Ch5  | `05-mcp-server.ts` | MCP Server，工具声明                       |
| Ch6  | `06-mcp-client.ts` | MCP Client，动态发现工具                   |
| Ch7  | `07-embedding.ts`  | 向量生成 `openai.embeddings.create()`      |
| Ch8  | `08-search.ts`     | 向量检索 `cosineSimilarity()` + 上下文注入 |

**设计亮点**:

- Zod 一次定义，多重用途（类型检查、运行时验证、Schema 生成）
- MCP 架构实现工具声明与调用解耦
- 流式输出使用 `for await...of` 迭代

**核心能力**: 解决"脏数据"和"失忆"问题

| 章节 | 文件                 | 核心概念                            |
| ---- | -------------------- | ----------------------------------- |

- `hybridSearch`: 向量检索优先，关键词检索补充

### 3. `03-agent-brain` - Agent 编排引擎

**核心能力**: 用 LangGraph 构建状态机驱动的复杂 Agent

| 章节 | 文件                    | 核心概念                                |
| ---- | ----------------------- | --------------------------------------- |
| Ch12 | `12-state-graph.ts`     | StateGraph 基础，Node/Edge/State        |
| Ch13 | `13-self-correction.ts` | 自我修复回路，Conditional Edge          |
| Ch14 | `14-human-loop.ts`      | 人机协作，`interruptBefore` + `MemorySaver` |
| Ch15 | `15-team-work.ts`       | 多 Agent 协作，Supervisor 模式          |

**架构演进**:

```
M1: while 循环 + if/else 硬编码
    ↓
M3: StateGraph 声明式图结构
```

**核心模式**:

```typescript
new StateGraph()
  .addNode('agent', agentNode)
  .addNode('tools', toolNode)
  .addEdge(START, 'agent')
  .addConditionalEdges('agent', shouldContinue)
  .compile()
```

### 5. `05-server-core` - NestJS 后端服务

**核心能力**: 解决并发、安全、成本问题

| 章节 | 模块      | 核心概念                           |
| ---- | --------- | ---------------------------------- |
| Ch20 | `chat/`   | Controller/Service/Module/DI      |
| Ch21 | `memory/` | Redis Checkpointer，会话持久化    |
| Ch22 | `common/` | ThrottlerGuard 限流 + AuthGuard 认证 |

**API 端点**:

| Method | Path           | 说明         |
| ------ | -------------- | ------------ |
| POST   | `/chat`        | 同步对话     |
| POST   | `/chat/stream` | SSE 流式对话 |
| GET    | `/health`      | 健康检查     |

**架构设计**:

```
Next.js (3000) ──▶ NestJS (3001) ──▶ Redis + Supabase
```

**关键特性**:

- `compatibility: 'compatible'` 模式兼容智谱 AI
- 三级限流: 1秒10次 / 10秒100次 / 60秒1000次
- 基于请求体哈希的 POST 缓存

## 八、哲学层洞察

这个项目体现了几个核心设计哲学：

1. **实用主义**: 每个章节解决一个真实问题，不追求理论完美
2. **渐进增强**: 从 `while` 循环到 `StateGraph`，从内存存储到 Redis，能力逐步叠加
3. **声明式优于命令式**: LangGraph 用图结构描述流程，而非 if/else 编排
4. **文档即代码**: GEB 协议确保架构意图与实现永远同步
