## 🎯 文件夹用途

### 核心职责

1. **技术讨论归档**: 将深度技术对话整理成结构化文档
2. **GitHub 同步**: 所有文档通过 `gh` CLI 创建为 Issue
3. **双向关联**: 本地文件与 GitHub Issue 互相引用

### 工作流程

```
AI 对话 → 整理成 Markdown → issue/*.md
                ↓
        gh CLI 创建 Issue
                ↓
        更新 .md 添加 Issue 链接
                ↓
        GitHub Issue ← 引用本地文件路径
```

### 1. 创建本地文档


```bash

  --title "📚 {标题}" \
  --body-file "issue/{文件名}.md" \
```

创建成功后：

1. 复制返回的 Issue URL
2. 更新本地 .md 文件的头部 `GitHub Issue` 字段
3. 可选：在 Issue 中添加评论引用本地文件路径

## 🔍 与其他文件夹的区别

| 文件夹       | 定位                   | 目标受众      | 生命周期     |
| ------------ | ---------------------- | ------------- | ------------ |
| `notes/`     | 学习笔记、知识积累     | 个人          | 长期迭代     |
| `doc/`       | 项目文档、规范         | 团队          | 长期维护     |
| **`issue/`** | **技术讨论、问题追踪** | **公开/社区** | **持久存档** |
| `sessions/`  | 对话归档               | 个人          | 短期存档     |

**核心区别**: `issue/` 中的文档必须发布到 GitHub Issues，面向公开讨论和协作。

## 💡 最佳实践

### 文档质量标准

- ✅ 结构清晰，章节分明
- ✅ 代码示例完整可运行
- ✅ 包含架构图（Mermaid）
- ✅ 对比分析有表格
- ✅ 核心要点有总结

### 何时创建 Issue

1. **深度技术分析** (如 M6 会话持久化)
2. **架构设计决策**
3. **性能优化方案**
4. **问题复盘总结**
5. **最佳实践指南**

### 何时不创建 Issue

- 简单的代码片段
- 临时的想法记录
- 未经验证的方案
- 仅个人可读的笔记
